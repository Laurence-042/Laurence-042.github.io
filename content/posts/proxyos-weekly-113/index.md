# 进展速记

## 本期假设 / 预期

**预期：**

这期的核心是做虚拟机验证了。预计本期 2 天中我会花 1 天玩通所有内容，然后花 1 天整理遇到的问题，如果顺利还能解决一点

**结果：**

又他妈的炸了！

上期本以为都通了，但实际通的是tmd我在开发环境跑过后直接复制到虚拟机的“已运行”发布包，真正刚构建出来、没被开发环境运行过的冷发布包，还是没法跑。

而这期就是把罪魁祸首python embedded彻底踢出去，换成了 python-build-standalone，连带着重新整理了 Mod 依赖和发布时的环境准备。

# 主要进展内容/本期关键判断点

> 我做出了哪些「如果错了也要付代价」的判断？

## 虚拟机验证，验证了个寂寞

要说为啥验证这么命运多舛，那就得说这个项目本身的定位了——真实python编程

也正因如此，ProxyOS 里的编程教程、脚本任务，还有mod系统都要用 Python（就像以前说的那样，绝大多数内容型的资产实际上都是作为名为Core的mod提供的，以此自行验证了mod系统的自由度、可维护性以及低廉的迭代成本）

但显然，准备开发环境这事连专业人员都头大，更别提没有编程基础的普通玩家了。

所以游戏会自带一份Python开发环境，玩家不用自己安装。

但坏就坏在这里。

之前在开发机上一直跑得好好的，开始准备发布后才陆续发现这份环境一堆毛病。

上期折腾了三天，终于在虚拟机里完成了启动和基础功能验证，本以为这期可以开始从头玩了。

结果新的发布包又无法运行，这我才意识到上期复制过去的发布包已经在开发机上运行过，里面有准备好的环境。全新构建出来直接复制进去仍然无法正常工作。

所以，上期那个“终于能启动了”就是个屁。

## Python embedded 不伺候了

原来用的是 Python 的 embedded 发行版，然后自己往里面补 pip、依赖和 Tk 等东西。

这期改成了 python-build-standalone，仍然是 Python 3.13.9，但解释器、标准库、pip 和 Tcl/Tk 由同一套发行物提供，不用继续自己拼了。也彻底摆脱了最麻烦的`._pth`管理。

## 然后是 Mod 的依赖
游戏本身的大部分内容也是以官方 Mod 的形式加载的，所以光有 Python 还不够，对应的依赖也得装好。

这次把玩家写脚本用的环境，和游戏后台加载 Mod 用的环境分开了。公共依赖固定版本，Mod 额外需要的东西装到单独的环境里，避免混在一起。

发布时直接把官方内容需要的依赖装好，玩家第一次打开时检查现有环境，能用就直接用。以后新增 Mod 需要补依赖，也先找包里有没有，确实缺了再联网。

以及，整个游戏文件夹换个位置后，这套环境还得能用。

为此又处理了一遍环境里的路径，并在发布构建里增加了搬到其他目录、断网后再检查的流程。

原计划是测剧情，最后又在折腾 Python 怎么安装依赖。绝了。
